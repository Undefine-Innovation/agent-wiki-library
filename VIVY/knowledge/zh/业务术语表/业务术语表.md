### Run
- 定义：Vivy 内核中对一次 Agent 执行的抽象，包含 Session、Message、RunEvent 等 domain 类型。每个 Run 必须恰好产生一个终态事件（PRD D-008），Run 状态机贯穿 runtime/engine 与 storage 层。
- 别名：run、agent run

### Journal
- 定义：Vivy 的事件溯源持久化层，以 Append-only 日志形式存储 Run 事件，支持 SQLite（默认）与 PostgreSQL 两种后端。所有变更通过事件追加写入，快照与压缩在 compaction 子包中处理。
- 别名：journal、event log

### Provider
- 定义：Vivy 对上游 LLM 服务的抽象适配层，位于 `internal/provider`，目前支持 OpenAI 兼容、Anthropic 与 mock。Provider 通过 YAML bundle 注册，对外暴露统一 Model 接口，屏蔽具体厂商差异。
- 别名：model provider、LLM provider

### ToolSpec
- 定义：工具的能力描述元数据，定义工具的名称、参数 schema、权限策略等，由 `internal/tools` 注册中心管理，并在运行前经审批策略（approval policy）校验后方可调用。
- 别名：tool spec、tool specification

### Approval Policy
- 定义：控制哪些 Tool 可在何种上下文中被自动调用的策略机制，位于 `internal/runtime/policy.go`。敏感工具（如命令执行、文件系统写入）默认需要人工审批后才能执行。
- 别名：policy、approval

### Budget
- 定义：针对单次 Run 的成本/配额控制机制，限制 token 消耗、调用次数或金额上限，防止失控调用。位于 `internal/runtime/budget.go`。
- 别名：budget、cost budget

### Sandbox
- 定义：隔离工具执行环境的沙箱机制，限制网络访问、文件系统权限等，确保危险工具在受限环境中运行。位于 `internal/runtime/sandbox_manager.go`。
- 别名：sandbox、execution sandbox

### MCP 服务
- 定义：Model Context Protocol 服务端配置，允许 Vivy 通过 MCP 协议连接外部工具服务器。UI 中的 MCP 面板支持 stdio 与 HTTP 两种传输方式，分别对应启动命令与服务地址。
- 别名：mcp、MCP server

### Audit Panel
- 定义：审计日志查看面板，展示三类日志（操作日志、系统日志、安全日志）并按日期筛选，最初位于右上角抽屉，后移植至中控台 Dashboard 页面。
- 别名：audit、审计面板

### 油前端规范（oil-frontend）
- 定义：Vivy UI 的设计与实现规范，要求使用 shadcn 基础组件、Zustand 状态管理、TanStack Router 路由、Tailwind CSS 样式，禁止私有设计系统与装饰性 CSS。MCP 面板重做即按此规范完成。
- 别名：oil frontend、oil-frontend

### 数字人（MATE）
- 定义：Vivy 已移除的数字人功能，包括设置页的 MATE 分区、宠物页面、3D 场景预览、ASR/TTS 预览等。项目明确不考虑内置数字人能力，相关 UI 与路由已整体删除。
- 别名：mate、数字人、pet

### Vivy Studio
- 定义：Vivy 的第一方日常开发 IDE，独立拥有分发生命周期，与 species-side 的 `vivy.exe` 分离。Studio 通过 `sdk/` 下的 vivy-sdk 二进制进行插件 verify/pack，不在 `vivy.exe` 中打开 Studio。
- 别名：studio、VIVY STUDIO

### Split 部署
- 定义：将后端与 UI 分离部署的模式，通过 `just build-split` 生成 `dist/vivy-backend.exe` 与 `dist/vivy-ui/` 静态资源。后端监听 :8787，UI 通过 Vite 代理 `/rpc` 到后端，仅限本机回环访问，非远程/多用户模式。
- 别名：split build、headless backend
