模块以 `main.go` 为入口，仅调用 `internal.Run` 分发命令；`internal/` 实现三个子命令：`verify`（`verify.go`）读取 `vivy-plugin.json` 并校验字段、导入限制与工具声明；`pack`（`pack.go`）解析 `--with` / `--out`，定位 species 根目录，通过 `go build -overlay` 将动态生成的 `zz_register.go` 注入到 `./cmd/vivy`，产出 EXE 与 `generation.json` 元数据；`inspect-artifact`（`inspect.go`）反序列化已打包产物。`plugin/plugin.go` 是对外暴露的唯一 API 边界，定义 `Plugin`、`Tool`、`Env` 接口及 `Seam`/`Grant`/`Effect` 白名单枚举，供用户插件实现；`internal` 仅可反向依赖该包，禁止引入 Eino/Journal 等运行时内部类型。依赖方向严格单向：`main → internal → plugin`，且 `pack` 还依赖 `agent-vivy/internal/domain` 以输出 `AssemblyRecipe` 与 `GenerationPhase`。测试用例集中在 `internal/testdata/` 下的坏用例（bad-eimport、bad-internal-import、bad-main、bad-os-open、bad-seam-journal、name-mismatch），配合 `verify_test.go`、`pack_test.go` 验证约束。
