## 简介
Agent-Vivy 是一个基于 Eino 框架的个人网关 Agent 运行时，提供后端服务与内嵌的 React + Vite 前端。默认使用 SQLite 作为存储，可选 Postgres；支持通过环境变量注入 Provider 密钥（如 OpenAI、Anthropic），并遵循“密钥不持久化”的安全约定。项目提供 just 任务脚本简化常用操作，也支持 Docker 一键运行。

## 环境要求
- Go 1.26+（Windows 默认路径为 C:\Program Files\Go\bin）
- Node.js 22+ 与 pnpm（用于前端开发与构建）
- 可选：just（用于执行 justfile 中的任务）
- 网络：GOPROXY 需设置为 https://goproxy.cn,direct（代理 golang.org 不可达时的镜像）

说明：
- README 中明确列出 Go、Node.js、pnpm 以及 GOPROXY 的要求，并指出 just 是可选的。
- go.mod 指定了 Go 版本为 1.26.4。

## 依赖安装
在仓库根目录执行以下命令完成依赖下载与校验：

## 配置设置
- 复制示例配置到本地：
  - cp config.example.yaml config.yaml
- 关键配置项说明：
  - server.addr：后端监听地址，默认 127.0.0.1:8787
  - storage.backend：存储后端，默认 sqlite；可选 postgres
  - storage.sqlite.path：SQLite 数据文件路径，默认 data/vivy.db
  - storage.postgres.dsn_env：Postgres DSN 所在的环境变量名，默认 VIVY_POSTGRES_DSN
  - providers.active：激活的 Provider 包，默认 openai
  - providers.bundle_dir：Provider 包目录，默认 fixtures/provider
  - runtime.mock：测试/离线开发时启用 mock 模式
- 密钥管理：
  - Provider 密钥通过环境变量注入，例如 OPENAI_API_KEY、ANTHROPIC_API_KEY
  - 配置文件只保存 env_key 名称，不保存真实密钥（遵循安全约定）

注意：
- 容器镜像默认使用 docker/config.yaml，将 addr 设为 0.0.0.0:8787，并将数据存储于 /data/vivy.db。
- 开发模式下，如果没有设置任何 Provider API Key，dev.ps1 会自动使用 config.dev.yaml 并开启 runtime.mock=true。

## 本地开发模式启动
推荐方式（一键启动后端与前端分离的开发循环）：
- 安装依赖后执行：
  - just dev
- 该命令会：
  - 检查端口 8787 与 3015 是否被占用
  - 自动安装 ui 依赖（如果尚未安装）
  - 启动后端进程（127.0.0.1:8787）
  - 启动 Vite 前端（127.0.0.1:3015）
  - 自动打开浏览器访问 http://127.0.0.1:3015
  - Ctrl+C 同时停止两个进程树

手动分步启动：
- 终端 1：启动后端
  - just run
- 终端 2：进入 ui 目录并启动前端
  - cd ui && pnpm dev
- 访问 http://127.0.0.1:3015

端口说明：
- 后端控制平面：127.0.0.1:8787
- 前端开发服务器：127.0.0.1:3015（Vite 默认端口）

说明：
- dev.ps1 会等待后端与前端各自端口就绪后再提示 ready。
- ui/package.json 中 dev 脚本指定 --port 3015。

## Docker 部署方式
单容器运行（内置 UI，SQLite 数据卷）：
- 构建并启动：
  - just docker-up
- 或等价 compose 命令：
  - docker compose up --build -d
- 访问：
  - http://127.0.0.1:8787

说明：
- Dockerfile 将前端静态资源构建进二进制，并在容器中暴露 8787 端口。
- docker-compose.yml 仅绑定 127.0.0.1:8787，避免对外暴露。
- 数据持久化到命名卷 vivy-data（容器内 /data/vivy.db）。
- 健康检查通过 /healthz 探测。

可选 Postgres 模式：
- 叠加 compose 文件启动：
  - docker compose -f docker-compose.yml -f docker-compose.postgres.yml up --build -d
- 该模式会：
  - 启动 PostgreSQL 服务
  - 设置 VIVY_CONFIG 指向 docker/config.postgres.yaml
  - 设置 VIVY_POSTGRES_DSN 环境变量供后端读取

注意：
- 文档强调 replica=1，不要对 vivy 服务进行 scale。
- 密钥通过环境变量注入（OPENAI_API_KEY、ANTHROPIC_API_KEY），不在配置文件中写入。

## 常见问题与故障排除
- GOPROXY 配置问题
  - 现象：go mod download 失败或超时
  - 解决：确保 GOPROXY 设置为 https://goproxy.cn,direct
  - 参考：just setup 会设置并下载依赖；dev.ps1 也会在开发时设置 GOPROXY

- 端口冲突
  - 现象：启动时报端口已被占用
  - 解决：停止占用 127.0.0.1:8787 或 127.0.0.1:3015 的其他进程
  - 参考：dev.ps1 会在启动前检测端口并抛出错误

- 数据库初始化问题
  - 现象：启动失败或无法读写数据
  - 排查：
    - 确认 storage.backend 与存储路径正确（sqlite 默认 data/vivy.db）
    - 容器模式下确认 /data 卷存在且可写
    - Postgres 模式确认 VIVY_POSTGRES_DSN 已设置且数据库可达
  - 参考：config.example.yaml 与 docker/config.yaml

- 密钥相关
  - 现象：Provider 调用失败
  - 解决：设置对应环境变量（OPENAI_API_KEY、ANTHROPIC_API_KEY）
  - 注意：不要在配置文件中写入真实密钥

- 开发模式未自动打开浏览器
  - 解决：使用 just dev 或 .\dev.ps1；也可添加 NoBrowser 参数以禁用自动打开

- 仅启动后端或仅启动前端
  - 后端：just run
  - 前端：cd ui && pnpm dev
