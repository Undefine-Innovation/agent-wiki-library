本模块是纯数据驱动的端到端快照测试集合，按被测入口划分为三个并列子目录：`acp/`（通过 `dsh --profile acp` 驱动 ACP 协议）、`sdk/`（通过 `@deepseek-ai/dsh-sdk-client` 调用 `dsh --profile sdk`）、`session/`（通过 `runLoaderSmoke` 直接启动 `dsh --profile headless`）。每个子目录以 `*.snapshot.ts` 为入口，使用 Vitest 的 `describe/it` 组织用例；每个场景一个独立文件夹，内含 `snapshot.yml` 清单声明 composition、recording、header pin、platform、permission、environment 等元信息，以及 `session.jsonl`（主会话）及可选 `session.N.jsonl` 子会话、`replay.override.json`、`workspace/` 种子与 `workspace.expected/` 期望结果。

运行流程统一为三模式：`DSH_SNAPSHOT=replay` 仅比对已提交 fixture；`record` 重新录制并写入 fixture；`refresh` 基于当前运行结果重写 fixture 中的可变占位符。所有 fixture 在写入前经 `normalizeSessionSnapshots`、`scrubRequestHeaders`、`redactSessionSnapshotIds`、`stabilizeFixtureMessageIds` 等工具函数归一化，确保跨平台稳定。系统提示与工具 schema 通过 `header.pin` 机制集中到单一 owner 场景的 `system-prompt.expected.md` / `tool-schemas.expected.json` 中，其他场景通过 `systemPromptSource` / `toolSchemasSource` 引用，避免重复。`cordis.yml` / `model.cordis.yml` / `cordis.snapshot.yml` 作为可组合的配置补丁，由 `materializeProfilePatch` 展开到 `.snapshot-patches/` 临时目录注入运行时。UI 相关场景位于 `web/`，断言 Markdown 形式的 UI 快照 (`ui.expected.md`、`terminal-card.expected.md` 等)。
