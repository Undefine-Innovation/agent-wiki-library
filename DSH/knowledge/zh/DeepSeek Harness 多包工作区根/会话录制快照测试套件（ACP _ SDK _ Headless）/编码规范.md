- 每个场景目录必须包含 `snapshot.yml` 清单，声明 `composition`、`recording`、`header`（含 `pin`/`class`/`changes`），并由对应入口脚本解析后动态注册用例。
- 会话输入与期望输出固定为 `session.jsonl` 系列文件，禁止在 `input.json` 中复制任务描述；多轮或多子会话使用 `session.1.jsonl`、`session.2.jsonl` 等连续编号。
- 系统提示与工具 schema 通过 `header.pin` 集中到单一 owner 场景的 `system-prompt.expected.md` / `tool-schemas.expected.json`，其他场景用 `systemPromptSource` / `toolSchemasSource` 以相对名或绝对路径引用，禁止重复持有。
- 工作区变更通过 `workspace.final: true` 配合 `workspace.expected/` 完整快照断言；未标记时要求最终工作区与初始一致，空结果使用 `.empty` 标记文件。
- fixture 写入前必须经 `scrubRequestHeaders`、`redactSessionSnapshotIds`、`stabilizeFixtureMessageIds`、`tokenizeSessionFixtureCwd` 等归一化工具链处理，保证跨平台与跨运行稳定。
- 配置补丁采用 `cordis.yml` + `model.cordis.yml` 的组合方式，运行时由 `materializeProfilePatch` 展开到 `.snapshot-patches/` 目录并通过 `--patch` 注入，避免直接修改共享 base 配置。
