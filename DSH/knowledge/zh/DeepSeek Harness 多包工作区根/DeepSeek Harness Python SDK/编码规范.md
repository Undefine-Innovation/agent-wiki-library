- 配置类统一使用 `@dataclass(slots=True)` 定义（如 `HarnessConfig`、`DeepSeekHarnessConfig`、`Notification`、`IncomingRequest`），以减少内存占用。
- JSON-RPC 响应体通过 Pydantic `BaseModel.model_validate` 强类型校验后再返回给上层调用者，错误则抛出 `JsonRpcError`。
- 异步 I/O 采用“reader/stderr 线程 + queue”模式：每个 `HarnessClient` 维护独立的 stdout 读取线程与 stderr 收集线程，所有跨线程状态变更通过 `threading.Lock` 保护。
- 资源生命周期遵循上下文管理器约定：`HarnessClient`、`NotificationSubscription`、`DeepSeekHarness` 均实现 `__enter__`/`__exit__`，确保进程关闭与订阅释放。
- 运行时可执行路径查找集中在 `deepseek_harness_runtime.__init__` 中，SDK 层只通过 `resolve_bundled_launch_args()` 获取 argv，不直接拼接平台路径。
- 错误信息在失败时附加 `_runtime_diagnostics()` 收集的退出码与 stderr 尾部，便于调试 dsh 进程崩溃。
