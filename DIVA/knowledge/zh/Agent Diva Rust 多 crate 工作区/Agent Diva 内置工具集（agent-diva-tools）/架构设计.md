本 crate 是 agent-diva 生态中的工具实现层，依赖 `agent-diva-tooling` 提供的 `Tool` trait、`ToolError`、`ToolRegistry` 等核心接口，并组合 `agent-diva-core`、`agent-diva-files`、`agent-diva-laputa`、`agent-diva-sandbox` 完成具体能力。
- 入口与导出：`src/lib.rs` 声明所有子模块并 re-export 每个工具结构体及公共类型（如 `sanitize_for_json`、`ActmemTool`、MCP 相关类型），构成对外 API 边界。
- 基础兼容层：`base.rs`、`registry.rs` 仅 re-export `agent_diva_tooling` 的 `Result`/`Tool`/`ToolError`/`ToolRegistry`，供上层以相同方式引用。
- 工具按职责分文件组织：文件操作（filesystem）、消息（message）、计划（planning）、工作区检查点（update_working_checkpoint）、执行待办（execution_todo）、后台任务（enqueue_background_task）、Spawn/Cron、Web（web）、Shell（shell）、附件（attachment）、Persona/Skill、WTF 彩蛋、以及 Memory CRUD（memory_add/list/get/search/update/remove/distill）。
- MCP 集成：`mcp_sdk.rs` 基于 crates.io 的 `rust-mcp-sdk` 实现 stdio 与 SSE 两种传输，封装 `McpClientWrapper` 管理连接生命周期，并通过 `McpSdkTool` 将远程 MCP 工具适配为本地的 `Tool`；提供 `probe_mcp_server`/`load_mcp_tools` 及其同步包装 `probe_mcp_server_sync`/`load_mcp_tools_sync`，支持在已有 tokio runtime 内使用 `block_in_place` 或创建新 runtime。
- 延迟激活工具：`tool_discovery.rs` 通过 `DeferredToolActivationHandle` 实现 `tool_search`，可在运行时搜索并激活 deferred 分区中的工具。
- 依赖方向单向：本 crate → `agent-diva-tooling`（trait）+ 各业务 crate（core/files/sandbox/laputa），不被其他工具 crate 反向依赖。
