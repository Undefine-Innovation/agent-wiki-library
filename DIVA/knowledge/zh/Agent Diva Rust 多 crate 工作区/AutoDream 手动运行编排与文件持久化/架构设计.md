模块以 `service.rs` 中的 `AutoDreamService` 作为对外入口，暴露 `trigger_manual_run` / `collect_inputs` / `execute_reflection_worker` / `execute_report_trigger` / `execute_scheduled_monthly_report` 等命令式 API；`worker.rs` 中的 `AutoDreamWorker` 负责四阶段（Orient → Gather → Consolidate → Propose）状态机编排，每个阶段维护 `AutoDreamReflectionStageRecord` 并写入事件日志。持久化层由 `layout.rs` 的 `AutoDreamStorage` + `AutoDreamPaths` 统一描述目录结构，所有 JSON 写操作通过 `atomic::atomic_write_json` 原子落盘，事件以 JSONL 追加到 `events.jsonl`，运行锁通过 `lock.json` 实现进程级互斥并支持过期恢复。依赖方向单向向外：service/worker 组合 `inputs`（输入采集）、`reflection`（可插拔 `SkillReflectionEngine` trait）、`reports`（报告写入）、`rhythm`/`monthly`（报告生成器）、`metrics`（全局指标）、`diagnostics`（诊断编码），并仅通过 `agent-diva-core` 的 `evolution`/`reports` 类型和 `agent-diva-laputa` 的 `MemoryHome`/`SkillHome` 访问外部权威存储，自身不直接修改 MEMORY.md 或权限库。
