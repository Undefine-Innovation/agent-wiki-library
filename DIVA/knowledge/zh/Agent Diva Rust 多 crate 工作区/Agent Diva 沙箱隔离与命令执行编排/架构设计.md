模块以 `lib.rs` 为入口，通过 Cargo features（`manager`/`orchestrator`/`platform`/`approval`/`guardian`/`filesystem`）按需编译子模块，形成可裁剪的 API 面。

- 策略层：`policy.rs` 定义 `SandboxPolicy`/`SandboxMode`/`AskForApproval`/`NetworkAccess` 等核心枚举，并桥接到 `agent-diva-core` 的 `SecurityPolicy`；`filesystem.rs` 提供基于路径的读写控制与 `WritableRoot` 受保护子路径机制；`rules.rs`、`command_rules.rs`、`exec_policy.rs` 实现 TOML 规则文件解析与前缀匹配审批策略。
- 编排层：`manager.rs` 暴露 `SandboxManager`，聚合策略、文件系统策略与平台执行器；`orchestrator.rs` 的 `ToolOrchestrator` 串联 Guardian → ExecPolicy → Sandbox → 重试/升级 的完整流程；`approval.rs`、`approval_coordinator.rs`、`governance_adapter.rs` 提供会话级审批缓存与外部治理适配。
- 自动批准：`guardian.rs` 实现 `GuardianManager` + `GuardianReviewer` trait + `GuardianRejectionCircuitBreaker`，支持 auto-learn、read-only 自动放行与熔断保护。
- 平台层：`platform/mod.rs` 按 `cfg(windows|linux|macos)` 选择具体实现，分别调用 Windows Restricted Token、Linux Landlock+Seccomp+Bubblewrap、macOS Seatbelt (`sandbox-exec`)；各平台 executor 在 manager/orchestrator 中条件导入。
- 依赖方向：orchestrator → manager → platform；orchestrator/guardian/exec_policy 共享 approval 子系统；所有层均依赖 `error.rs` 统一错误类型，并通过 `tracing` 记录日志。
