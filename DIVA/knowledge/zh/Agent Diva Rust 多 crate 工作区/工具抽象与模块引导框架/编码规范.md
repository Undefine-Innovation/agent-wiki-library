- 所有跨任务共享的可变状态通过 `Arc<RwLock<T>>` 包装（如 `ModuleCtx.config`、`presence`、`ActiveDeferredTools`、`DeferredToolActivationHandle.catalog`），保证线程安全且可克隆。
- 错误类型统一使用 `thiserror::Error` 派生，并为每个变体提供稳定的机器可读 `code()` 字符串，同时实现 `CategorizeError` 映射到 `agent_diva_core::error_category::ErrorCategory`。
- 对外暴露的 JSON Schema 输出经 `canonicalize_json` 递归排序对象键以保证字节级稳定，配合 `ToolDefinitionSet.core_count` 维持 Core/Deferred 分区边界不变。
- 工具执行路径遵循固定模板：查找工具 → 校验参数 → 应用超时 (`tokio::time::timeout`) → 调用 `sanitize_tool_output` → emit `AuditEvent::ToolExecuted` → 返回结构化结果。
- 模块生命周期通过 `Module::dependencies()` 声明式描述，由 `ModuleRegistry::resolve_start_order` 用 Kahn 算法计算启动序，并由 `Bootstrap::start_all` 在失败时反向调用已启动模块的 `stop` 进行回滚。
- 延迟工具通过 `ToolSchemaPartition::Deferred` 注册并进入独立 catalog，需先经 `search_deferred` 关键词匹配才能加入当前 turn 的 `ActiveDeferredTools` 集合，从而限制可见工具数量至 `MAX_ACTIVE_DEFERRED_TOOLS`。
