模块以 `base.rs` 中的 `LLMProvider` trait 为核心边界，统一暴露 `chat` / `chat_stream` / `get_default_model` / `dynamic_context_transport` / `prompt_cache_profile` 等方法，并通过 `DynamicProvider`（`lib.rs`）支持运行时热替换底层实现。

- 具体客户端：`openai_compatible.rs`（通用 OpenAI 协议）、`anthropic.rs`（原生 Messages API）、`ollama.rs`、`deepseek_v4_dsml.rs` 均实现同一 trait；`final_wire.rs`、`report_narrative.rs`、`transcription.rs` 提供附加能力。
- 构造与装配：`factory.rs::build_llm_provider` 依据 `registry::ApiType` 选择客户端，并用 `tap::ProviderTap` 包装以注入速率限制、审计事件与重试监听；`registry.rs` 通过 `include_str!("providers.yaml")` 加载内置 ProviderSpec 列表，按 model 关键词匹配路由。
- 目录与发现：`catalog.rs::ProviderCatalogService` 聚合 `ProviderRegistry` 与用户自定义配置，生成 UI 视图并提供增删模型、保存自定义 provider 等操作；`discovery.rs` 对 OpenAI 兼容端点发起 `/models` 请求进行运行时模型发现，失败时回退到静态列表。
- 横切能力：`retry.rs` 提供指数退避 + jitter 的重试封装（429 直接返回 `RateLimited`，5xx 重试最多 3 次），`http_util.rs` 统一构建带超时与代理的 reqwest Client，`base.rs` 内嵌 `StreamingUtf8Decoder` 处理跨 chunk 的 UTF-8 边界。
- 依赖方向：本 crate 仅向上依赖 `agent-diva-core`（错误分类、配置结构、审计、速率限制），不反向被 core 引用，作为纯提供者集成层。
