单二进制 crate（`src/main.rs`），通过 clap 定义 `Memory`/`Experience` 两大子命令，每个子命令统一暴露 `DryRun`/`Apply`/`Rollback` 三态操作；`Apply` 必须通过全局 `--features memory|experience|workspace_identity` 显式开启，由 `require_feature` 强制校验。业务逻辑按领域拆分到三个独立模块：`typed_memory.rs` 负责从 MEMORY.md/HISTORY.md/Laputa JSON 解析并导入 TypedMemoryStore，使用 `.laputa/migrations/<id>/applied-manifest.json` 记录迁移元数据与备份路径，并通过 `MemoryRecordMigration::dry_run/execute` 生成可重放工件；`experience.rs` 扫描会话消息中的 tool 调用，经 `ExperienceJournal::session_backfill_evidence` 生成 payload-free 证据写入 `.agent-diva/autodream/experience/migrations/<id>/manifest.json`；`workspace_identity.rs` 检测 legacy_path_workspace_id 与 canonical_workspace_id 差异，借助 `TypedMemoryStore` 提供的 `open_canonical`/`rollback_canonical_identity` 完成身份归一化。所有模块均依赖 `agent-diva-core`（workspace identity、memory/session 类型）和 `agent-diva-laputa`（TypedMemoryStore、LaputaSection、atomic_write_json），本 crate 不引入运行时依赖，仅作为离线 CLI 被外部脚本调用。
