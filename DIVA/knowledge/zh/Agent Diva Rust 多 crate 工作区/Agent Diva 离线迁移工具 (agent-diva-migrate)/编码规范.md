- 每个迁移领域模块对外暴露 `dry_run`/`apply`/`rollback` 三件套，并以带 `migration_id`、`manifest_path`、`integrity` 等字段的 Report 结构体返回结果，便于 JSON 输出。
- 每次 `Apply` 在 `.laputa/migrations/<id>/` 下持久化 `applied-manifest.json`（或 experience 的 `manifest.json`），记录输入摘要、备份路径与状态机字段（Prepared/Applied/RolledBack），用于幂等重放与回滚。
- `Apply` 操作一律先创建 SQLite 备份（如 `memory-before.sqlite3`），失败时自动 restore 并在成功后写入 manifest，保证可逆性。
- 迁移 ID 由输入摘要派生（如 `gmh24-<input_digest[:16]>`、`experience-<records_digest[:24]>`），确保相同输入可重放且不同输入产生新迁移目录。
- 对 destructive 的 `Apply` 通过全局 `--features` 白名单强制放行，`DryRun`/`Rollback` 始终允许，由 `require_feature` 集中校验。
- 源文件校验拒绝符号链接、非普通文件、逃逸 source_root 的路径以及包含 `.mentle` 组件的路径，防止恶意导入。
