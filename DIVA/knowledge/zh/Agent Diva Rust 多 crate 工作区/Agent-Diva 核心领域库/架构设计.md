本 crate 以 `lib.rs` 为唯一入口，按领域划分出多个平级子模块（bus、config、cron、evolution、governance、heartbeat、memory、planning、presence、quality、reports、scheduler、security、session、supervised、todo、token_ledger、tool_artifact、utils），并通过顶层 `pub use` 暴露关键类型。
- 错误与可观测性：`error.rs` 定义统一的 `Error`/`Result` 枚举并实现 `From` 转换；`audit.rs` 通过 `tracing::info!(target: "audit")` 输出结构化 JSON 事件，并由 `audit_sink` 全局 sink 转发，形成单一审计出口。
- 安全边界：`security/` 集中路径校验、注入检测、PII 脱敏、指令层级、技能信任、速率限制与拒绝熔断，被其他模块作为横切能力调用。
- 治理与计划：`governance/` 提供 fail-closed 的审批协调器与策略账本，`planning/` 基于其 `governance_adapter` 驱动 plan→step→todo 生命周期，并通过 `report_store` 持久化报告。
- 记忆系统：`memory/` 以 `provider` trait 抽象后端，`crud`/`actmem`/`recall`/`working` 分层协作，配合 `workspace_identity` 生成稳定的 workspace ID。
- 会话与执行：`session/` 管理会话准入与存储，`supervised/` 提供 Run 的执行器、回收器与存储，`scheduler/` 桥接外部调度器并在沙箱中运行任务。
- 配置与基础设施：`config/` 使用 `config` crate + serde schema 加载/校验配置；`bus/` 提供事件队列；`logging.rs` 初始化 tracing 订阅；`rate_limiter.rs`、`experience.rs`、`reasoning.rs` 等提供通用原语。
依赖方向单向向外：各子模块仅依赖同 crate 内其它子模块及工作区共享依赖（tokio、sqlx、serde、tracing 等），不反向依赖上层 agent 实现。
