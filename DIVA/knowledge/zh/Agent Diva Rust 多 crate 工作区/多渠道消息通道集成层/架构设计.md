模块以 trait + manager 的插件式架构组织：`base.rs` 定义 `ChannelHandler` trait（start/stop/send/is_allowed）与共享基类 `BaseChannel`（含 allow_from 白名单、deny_by_default 策略、`handle_message` 封装入站消息并写入 `mpsc::Sender<InboundMessage>`），每个平台通道文件（dingtalk/discord/email/feishu/qq/telegram/neuro_link 以及可选的 slack/matrix/irc/mattermost/nextcloud_talk/whatsapp）实现该 trait；`manager.rs` 中的 `ChannelManager` 通过 `channel_validation` 按名称匹配配置字段，在 `initialize`/`update_channel` 中按需构造具体 Handler 并存入 `HashMap<String, ChannelHandlerPtr>`（`Arc<RwLock<dyn ChannelHandler>>`），对外暴露 `send`、`list_channels`、`is_channel_running` 等统一接口；`common/mod.rs` 提供跨通道复用的 HTTP 客户端构建与媒体下载工具。依赖方向单向指向 `agent-diva-core`（`bus::{InboundMessage, OutboundMessage}`、`config::schema::Config`）与 `agent-diva-providers`，各通道之间无相互引用。可选通道通过 Cargo feature（`channel-slack`、`channel-whatsapp`、`channel-matrix`、`channel-irc`、`channel-mattermost`、`channel-nextcloud-talk`）编译开关控制，默认仅启用已验证通道。
