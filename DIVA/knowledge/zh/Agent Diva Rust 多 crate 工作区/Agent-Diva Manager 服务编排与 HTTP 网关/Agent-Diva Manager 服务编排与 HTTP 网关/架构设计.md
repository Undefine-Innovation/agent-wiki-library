模块以 `lib.rs` 为 crate 入口，统一暴露 `Manager`、`AppState`、`build_router`、`run_server` 等对外 API。
- 状态层：`state.rs` 定义进程级 `AppState`（持有 MessageBus、ConfigLoader、SkillHome、MemoryHome、AutoDreamService、PersonaService、ApprovalCoordinator、AskUserCoordinator 等）以及跨所有服务的 `ManagerCommand` / `ProviderCommand` 枚举，作为唯一命令总线。
- 命令循环：`manager.rs` 中的 `Manager` 结构体在 `run()` 中通过 `tokio::select!` 从 `mpsc::Receiver<ManagerCommand>` 消费指令，并分派到 `handle_*` 方法；对需要与 AgentLoop 交互的操作通过 `runtime_control_tx` 发送 `RuntimeControlCommand` 完成双向通信。
- 子服务：每个领域封装为独立 Service 并通过 `AppState` 共享——`mcp_service.rs` 管理 MCP Server 配置的 CRUD 与连接探测；`skill_service.rs` 负责 Skill ZIP 解析、安装与 Marketplace 快照导入；`planning_service.rs` 提供带治理审批的计划报告与执行 Todo 管理；`file_service.rs` 处理文件上传；`approval_service.rs` 封装审批协调；`marketplace.rs` 提供市场技能检索。
- HTTP 网关：`server.rs` 用 axum 构建 Router，按 `/api/chat`、`/api/skills`、`/api/mcps`、`/api/providers`、`/api/plan-reports`、`/api/memory`、`/api/persona`、`/api/autodream`、`/api/audit` 等前缀划分路由组，全部挂载 `AppState`，并通过 `handlers::*` 把 HTTP 请求转为 `ManagerCommand` 经 channel 投递给 Manager 循环。
- 依赖方向：HTTP handlers → Manager 命令循环 → 各 Service → 底层 agent_diva_* crate；Manager 不直接持有具体 Service 实例，而是通过 `AppState` 或 `ensure_planning_service` 懒加载，避免循环依赖。
