- 所有外部可调用操作都通过 `ManagerCommand` 枚举表达，handler 仅负责把 HTTP 参数包装成命令并通过 `AppState.api_tx` 发送，再由 Manager 循环统一派发。
- 跨进程/跨任务同步响应使用 `tokio::sync::oneshot::Sender<T>` 随命令一起传递，调用方 await oneshot 接收结果，错误统一包装为 `Result<T, String>`。
- 子服务以无状态 struct 形式暴露（如 `McpService`、`SkillService`），通过 `new(loader)` 或 `from_home(home)` 构造，读写配置均走 `ConfigLoader::load/save` 原子化持久化。
- HTTP 路由按功能域拆分为独立的 `*_routes()` 函数（如 `runtime_routes`、`provider_routes`、`planning_routes`），再在 `build_router` 中 `.merge(...)` 组合，便于新增模块时只改一处合并点。
- 对外 DTO（`McpServerDto`、`SkillDto`、`ToolsConfigResponse` 等）与内部配置结构分离，通过 `From`/`to_dto` 转换，避免泄露内部字段（如隐藏 API Key）。
- 输入校验集中在服务层（如 `validate_skill_zip_size`、`validate_skill_slug`、`validate_server`），失败返回 `anyhow::Error`，由上层 handler 统一转换为 JSON 错误响应。
