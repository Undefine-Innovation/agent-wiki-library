以 `lib.rs` 为对外 API 入口，暴露 `Manager`、`run_local_gateway`、`build_router`、`AppState`、`ManagerCommand` 等核心类型；`server.rs` 基于 axum 构建路由表，`handlers/` 下每个模块对应一组 HTTP 端点（approvals、planning、mcp、skill、file、marketplace、autodream、laputa、workspace、logs、persona、memory、todo、audit、command_approvals、provider_companion、health、token_stats），全部通过共享的 `state::AppState` 访问单例 `Manager`；`manager/` 提供 companion_admin、provider_admin、runtime_control 等管理面能力；`runtime/` 封装启动引导、任务运行环境与优雅关停；各业务服务（approval_service、mcp_service、planning_service、skill_service、file_service、marketplace）作为中间层把 HTTP 请求翻译为对底层 agent-diva-* crate 的调用；依赖关系单向：handlers → service_* → manager/runtime → agent-diva-core/agent/providers/channels/tools/sandbox/autodream/laputa/files。
