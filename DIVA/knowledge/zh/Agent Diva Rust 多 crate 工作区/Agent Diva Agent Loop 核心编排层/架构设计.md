本 crate 通过 `src/lib.rs` 统一暴露各子模块（agent_loop、compaction、consolidation、context、context_assembly、mask、planning、tool_assembly、tool_config、subagent 等），由 `AgentLoop` 在 `run()` 中持有 MessageBus、LLMProvider、SessionManager、ToolRegistry、SubagentManager、MemoryProvider 等共享资源，并在每次 inbound 消息时调用 `process_inbound_message` → `loop_turn` → `turn::{admission,prompt,iteration,finalize}` 完成一轮处理；每轮通过 `build_agent_tools` + `ToolAssembly` 根据当前 mask、plan_phase、execution_session_id、background_task_context 动态重建工具表面，使 planning、mask、subagent、cron、sandbox 等能力在同一 turn 内协同。跨子模块的协作契约集中在：`agent_diva_core::bus::{MessageBus, InboundMessage, OutboundMessage, AgentEvent}` 作为事件总线，`agent_diva_tooling::ToolRegistry` 作为工具注册中心，`agent_diva_core::security::{ActionTracker, RejectionCircuitBreaker}` 与 `token_estimate`/`context_budget` 共同实现全局超时、拒绝熔断与令牌预算控制，`memory_boundary` 提供统一的 MemoryProvider 注入点供 context、compaction、consolidation、subagent 共享。启动阶段通过 `with_tools` / `with_toolset` / `with_tools_and_memory_provider` 三种构造器把 tool_config、file_manager、runtime_control_rx、memory_provider 等外部依赖装配进 AgentLoop，再由 `loop_runtime_control` 在运行期接收 RuntimeControlCommand 动态调整策略。
