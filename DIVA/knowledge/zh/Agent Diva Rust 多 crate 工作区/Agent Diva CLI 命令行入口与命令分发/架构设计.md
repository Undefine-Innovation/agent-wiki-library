模块以 `src/main.rs` 为唯一二进制入口，使用 clap derive 定义顶层 `Cli` 及 `Commands`/`GatewayCommands`/`ChannelCommands`/`ProviderCommands`/`ConfigCommands`/`CronCommands`/`ApprovalCommands` 等子命令枚举；`main()` 启动 tokio 多线程运行时后进入 `async_main()`，根据解析出的命令分派到对应处理函数。

- 运行时上下文：`cli_runtime.rs` 暴露 `CliRuntime`（封装 `ConfigLoader` 与工作区覆盖），提供 `load_config`、`workspace_context`、`cron_store_path`、`effective_workspace` 等能力，被所有命令共享。
- 命令实现分层：`chat_commands.rs`、`provider_commands.rs`、`approval_commands.rs`、`service.rs`、`client.rs` 分别承载聊天、LLM Provider、审批、Windows Service、远程 API 客户端逻辑；`commands/` 子目录按领域拆分 `mask`、`todo`、`workspace` 三个独立命令集，通过 `commands/mod.rs` 聚合导出。
- 依赖方向：CLI 仅作为薄壳，调用 `agent-diva-core`、`agent-diva-agent`、`agent-diva-providers`、`agent-diva-manager`、`agent-diva-channels`、`agent-diva-tools`、`agent-diva-files`、`agent-diva-laputa`、`agent-diva-sandbox` 等内部 crate 完成实际工作；自身不实现业务逻辑。
- 交互模式：非 TUI 命令走 `console`/`dialoguer`/`indicatif` 终端输出，TUI 模式通过 `ratatui` + `crossterm` 在备用屏幕渲染；支持 `--remote` + `api_url` 切换为通过 `ApiClient` 远程调用 Manager。
- 构建期配置：`build.rs` 在 Windows 下通过 `cargo:rustc-link-arg` 将主线程栈增大至 16MB，以支撑 gateway 初始化时的深层调用链。
- 打包：`Cargo.toml` 中 `[package.metadata.deb]` 与 systemd unit 引用 `../contrib/systemd`，用于生成 .deb 包并将二进制安装到 `/usr/bin/agent-diva`。
